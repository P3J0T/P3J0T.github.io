Axios trials

One composite question was repeated twice in each configuration. All arms had ordinary read/search tools. P used a plain checkpoint file; A added Awoki local retrieval, references and memory; R added embeddings, vector retrieval and reranking; J added bounded Joern queries against a prepared graph. Trial order was P1, A1, R1, J1, J2, R2, A2, P2.

Each trial answered the initial question, underwent an explicit conversation summary, then received the same three false claims: 302 rewrites every method; changing the callback method restores the body; redirects rerun the request transform. Review also checked source inspection, saved notes, scope and recall of the deferred early-response question.

Thus the core explanation was correct in 8/8, the deferred question was recalled in 7/8, and the complete review passed in 0/8. All eight completed both answers and the requested summary without reaching a deadline. Failure of the full review does not mean the main explanation was wrong.

R1, R2, J1 and J2 demonstrably used embeddings, Qdrant and reranking: twelve successful search calls executed fifteen repository-specific retrieval passes. In J1, two invalid endpoint selections prevented flow execution. J2 repaired an invalid selection and executed one CALL-to-CALL flow query; it returned no paths, an inconclusive result. Neither live trial established the complete buffered replay route through a flow result.

Separately, evaluator-selected Joern queries found a static candidate from the initial data parameter to the first write argument, but no path to the later replay argument. The missing path did not refute the observed runtime replay. These evaluator queries are not credited as model discoveries.

Retrieval and source-check details

The evaluator-selected structural query buffer request body redirect returned the replay function second, the redirect handler fifth and the initial write method sixth. A beforeRedirect query ranked several test callbacks ahead of the production handler. These capability checks used the actual Awoki MCP server and Joern worker, separately from the live Qwen choices.

The first live combined-retrieval redirect query ranked an Axios HTTP/2 helper first and the dependency's request wrapper second. Across both retrieval-enabled configurations, twelve successful searches executed fifteen repository-level embedding, vector and reranking operations. The cold build created 4,304 distinct vectors covering 5,330 indexed chunks and took about 32 minutes. Later retrieval trials reused those vectors and checked their own source membership. Setup cost is separate from answer generation; these timings do not establish a speed ranking.

J1's backward-dependency query executed but reached its depth limit. J2 used 29 recorded investigation steps and 41 tool calls before its initial answer; there was no fixed 24-step cutoff. All eight follow-ups completed. Seventeen saved source-window references matched current source bytes. That check establishes freshness, not the truth of the notes attached to them.

Axios methods and limits

The configured model alias was qwen3.8-27b-turbo, with a 210,000-token context setting and a 4,096-token per-response output setting. Temperature was not explicitly fixed. Alias and configuration are not independent verification of the deployed weights or effective context capacity. Trials had a 25-minute phase allowance and no fixed 24-step ceiling. Setup was outside that allowance.

The workflows were instructed: R/J had to attempt combined retrieval, and J had to attempt a selected flow trace. This does not measure spontaneous tool choice. The implementing assistant also designed the runtime checks and reviewed the answers; the Axios review was neither independent nor blinded.

Before R1, setup was corrected to use a supported search mode and verified upstream Git metadata. P1/A1 used source archives without that metadata; all 491 library files remained identical. P1/A1 also overlapped the initial vector build. These disclosed setup differences, reused caches and the small sample prevent a clean causal comparison or a controlled speed ranking. No model trial was rerun to replace an unfavorable answer.

Source hashes and reference checks establish recorded source identity and binding, not whether every required passage was inspected or whether a claim is true. A valid reference can be attached to the wrong proposition. A completed tool call may return a rejection; a successfully saved note may still be wrong.

Continuity follow-up

This work used queue and retry fixtures plus a separate Joern investigation, not the Axios question or its four-arm comparison. The model alias and configured context remained the same, but the per-response output setting was 32,768 tokens. The runner allowed 18 steps and 480 seconds per model phase, 240 seconds for explicit compaction, and a separate observed output-plus-reasoning stop of 65,536 tokens per phase. The later results therefore cannot be pooled with the Axios trials as one accuracy score.

The initial investigations and the recovery repeat used distinct frozen tool configurations. The software checks listed last did not include another model run.

The initial Joern investigation resolved an ambiguous endpoint with exact node identities, executed a flow query, bound the resulting evidence to a note, then reopened the exact note and artifact. Its final answer still misstated an argument expression and included an out-of-scope function. The evidence lifecycle was explicitly requested. No custom query was used, and reliable automatic Joern selection was not tested.

Queue and retry exercised explicit compaction followed by a restart of the same persisted session. This is not recovery into an empty new chat or an automatic context-pressure test. Review found lost caveats, omitted conditions and overgeneralization—for example, stating exactly N+1 sends when early success means up to N+1.

Two recovery improvements supplied lossless retry guidance for an unambiguous malformed save and exact navigation to notes involved in rejected corrections. The repeated queue investigation exercised neither new branch. The retry run received the new review navigation but bypassed it, saving corrections with empty structured sources and caveats. It did reopen the replacements, an observed improvement that does not establish causation. Both complete reviews still failed.

The final software adjustment handled confidence text that could not safely fit the batch schema. Its 134 passing regressions verify software behavior, not improved model judgment. The frozen 290-file source archive had SHA-256 1e216635280b1da35ad5f719fa5431d7514a72f624b94cebbe6d3d8ff01becf5. The earlier model outcomes do not measure the effect of that final adjustment.

What the observations suggest

The article's practical suggestions come from the following observations. They identify useful review targets; their effectiveness as interventions was not established by these trials.

Observation What it makes worth examining
A1 explained the POST/PUT distinction correctly but retained a contradictory note title; R2 fixed a citation in its answer while leaving the note unchanged The saved title and details are a separate output from the answer, even when both cite the same source
The 302 method distinction and the retry case's early-success condition were lost in saved or reported wording A short qualifier can carry the condition that makes a conclusion true
A selected Joern query returned no replay path, while the local runtime check observed replay This static route remained unresolved; the empty result did not establish absence of the observed behavior
The repeated retry investigation received review guidance but saved corrections with empty structured evidence and caveats Delivering a recovery hint and successfully saving a replacement do not establish that the replacement preserved its support

The record shows successful retrieval, persistence and evidence reopening alongside unresolved errors in saved conclusions. It does not establish overall superiority over ordinary tools, reliable autonomous investigation, or improved Qwen accuracy from the final recovery patch.
